## Implemented behavior

They enforce native management IAM action/ARNs, limits, region/scope consistency and explicit unsupported-field errors. New AddPermission/GetPolicy/RemovePermission operate on function resource policies, with API-specific local SourceArn grants, revision guards and deletion/recreation protection. No real AWS or arbitrary HTTP target is used.

Actual local HTTP invokes fixed CPython/WASI with the saved function role and existing bounded S3/SSM bridge. Function code, service grant and role trust are captured in one SQLite transaction before execution. The event retains actual route versus resource template, duplicate query/header values and application Bearer data, while stripping simulator/session authority and all cookies. SourceArn mismatch or removal denies execution. Output parsing and expanded-header bounds fail explicitly; guest errors return sanitized502.

All Cookie headers are discarded after host authentication, including unrelated local application sessions shared across ports. An actual browser carries an extra dummy local-app cookie; the deployed function rejects any cookie and still returns42, proving that the cookie does not enter its event. Explicit application Bearer data is retained.

The transport deliberately downloads untrusted responses as non-executing attachments, filters protected cookies/navigation/CORS/authority headers, and imposes restrictive CSP/nosniff/no-store. An actual authenticated browser navigation to guest HTML downloads response.bin without executing its script, changing operator cookies or sending its attempted authority request. Active browser application hosting is not supported.
