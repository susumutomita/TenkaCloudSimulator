# REST API Gateway vertical slice and current projection contract

Target the existing WP template's REGIONAL RestApi, root/proxy Resource, ANY/NONE Method, Lambda AWS_PROXY integration, immutable Deployment, Stage and SourceArn-bounded Lambda Permission. The bounded native REST subset is documented in [apigateway.md](../apigateway.md); the full original WP problem remains unavailable. Native control-plane records alone do not satisfy problem acceptance.

The initial Kumo ce37a8f routing/event adaptation is historical and superseded by the provider-owned route program and explicit native-request event projection. Preserve the fixed source hashes and original MIT notices in [historical provenance](../../third_party/kumo-apigateway.json). Kumo remains a useful registry/protocol/SDK-endpoint/service-wiring design reference, not the runtime engine. Existing AWS-owned SQLite storage/transactions are retained. Deployment snapshots must stay immutable; stages point to a specific snapshot. Preserve actual path separately from the resource template, duplicate query/header values and body semantics. Do not copy upstream HTTP dispatch into host networking: invoke the bounded saved-role Python runtime in-process.

Matching validates segment cardinality and literal constraints before publishing captures; interior empty/dot/escaped segments are not cleaned or decoded. The event projection retains duplicate application values, required null/empty distinctions, actual method/path/body, the encoded event cap and immutable caller inputs. It excludes transport authority rather than serializing the original request. These are scoped behavior contracts, not a clean-room or full implementation proof.

Every operation keeps native IAM actions/ARNs and strict unsupported-field errors. API Gateway service invocation additionally requires the function's limited resource permission with synthetic account/region and matching execute-api SourceArn. No guest-selected principal, endpoint, host credentials or network client is introduced. Guest events strip all cookies, simulator headers and AWS session/signature credentials, retaining explicitly supplied application Bearer data.

The local initial transport prevents untrusted Lambda HTML/redirects from acquiring the console's browser origin or opaque operator cookie. API-only mode forces downloaded, non-executing responses, filters protected response headers/redirects and keeps the existing local-token boundary. Active browser app hosting remains unavailable until a separate-origin design is implemented and tested. Merely using another path on the console origin is unsafe; another port also requires strict Origin checks and care because cookies are not port-scoped. Do not silently claim browser-hosting parity.

Acceptance before advertising: real SDK create→method/integration→deploy/stage→actual HTTP→native Python execution/role SDK effects→delete; denied/missing SourceArn permission; immutable old deployment after a method edit; malformed proxy response; bounded body/deadline; credential/cookie redaction; protected HTML/redirect handling; restart persistence; separate authenticated teams with identical names; real console manipulation and useful Scalar examples; regressions/formal checks. Full original WP still needs WAFv2 AND/URI/SQLi rules, custom-resource callbacks and all original grading checks. Preserve the current catalog flags and keep unsupported problems unavailable.
