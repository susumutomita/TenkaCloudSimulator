# ブラウザーから教材を始めるための要件案

授業で先生が教材のリンクを配り、生徒が同じ初期状態から自分の環境で練習を始める場面を想定する。次の授業で続きを開くのは本人だけで、配ったリンクは別のクラスでも使えるようにしたい。以下は [Issue #452](https://github.com/susumutomita/TenkaCloudSimulator/issues/452) の検討案である。公開先、認証方式、提供時期は未決定。

## 1. 教材を開く

現行版では、運用者がシミュレーターを起動し、学習者はブラウザーで自分に発行された参加者資格情報を使う。チームごとにプロセス、SQLite、トークンの発行元を分ける。[起動手順](../start.md)と[ブラウザーセッション](../console-sessions.md)を参照。

| 提供方法 | 学習者が最初にすること | 採用判断に必要な確認 |
| --- | --- | --- |
| 現行のローカル版 | 配布された教材の手順を開き、起動済みの環境にサインインする | 学校の端末で誰が起動を担当できるか。インストール権限を持たない生徒も授業に参加できるか。 |
| Web 常設 | 教材リンクを開き、サインイン後に割り当てられた環境で開始する | 学校アカウントの利用条件、同時利用人数、環境の停止・再開と費用。Google 認証と Cloudflare はそれぞれ候補。 |
| ブラウザー単体版 | 教材を読み込み、その端末内で開始する | 教材が使う API と SQLite の動作、タブを閉じた後の復元、学校の共有端末でのデータ消去。別端末での再開には別途保存先が要る。 |

Web 常設を選ぶ場合、ホストがサインインした学習者と演習環境を対応付け、その環境だけを操作できる参加者セッションを発行する。教材リンクを経由したログインでも選んだ教材を保持する。受け入れ時は、同じリンクを開いた二人が同じ名前のリソースを作っても互いに見えないこと、共有端末でサインアウトした後に次の利用者から前の環境を開けないことを確かめる。

## 2. リンクから初期状態を再現する

共有の最小単位を**公開教材のテンプレート ID と固定版**とする。例えば「ストレージ入門の第3版」を示すリンクなら、受け手の新しい環境に第3版で定義したリソースと初期値を用意する。作り手のリソース ID、操作途中の SQLite、回答、ユーザー識別子、トークンは URL に含めない。途中まで解いた状態を再現したい授業では、その状態を個人情報を含まない別の公開テンプレートとして用意する。

リンクを開くと、まず教材名と版を表示し、「新しく始める」と、自分の保存分がある場合の「続きから」を選べるようにする。既存の演習状態を書き換える操作はリンクを開くだけでは行わない。第4版の公開後も第3版のリンクで同じ課題を再現できること、未知の ID や提供終了の版では理由を表示して開始前に止まることを受入条件とする。

## 3. 本人の記録を見返す

個人ダッシュボードを提供する場合の最小案は、本人が開始した教材名・版、進行状態（学習中／完了）、最終利用日、自分の環境を再開する操作である。完了は教材側で定義した条件を満たしたときに記録する。教材定義と採点は TenkaCloudChallenge、学習者と環境の割当・履歴は提供側が担当する案とし、シミュレーター本体は演習リソースの状態を扱う。

運用開始前に、学校・提供者が保存項目、保持期間、期限が来た演習環境と履歴の扱いを決める。本人が保存内容と期限を確認し、記録を削除できることを確かめる。削除後は本人の一覧と再開先からその記録が消え、配布済みの公開教材リンクは引き続き他の学習者が使えることを確認する。

次の判断は、端末へのインストールと別端末での再開が授業に必要かどうかである。まず既存のローカル版で開始時の手順とつまずきを確認する。その結果と学校のアカウント・記録保持条件を基に、Web 常設とブラウザー単体版のどちらを試作するかを決める。
