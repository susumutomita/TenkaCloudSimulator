# Local AWS Support cases

Each team's simulator keeps its own case history in SQLite. In the authenticated Console, open **Services → AWS Support** to create a practice case, attach a file, post a follow-up and resolve it. The case detail shows the stored filename and offers an explicit download. Submitted material stays on the local simulator. AWS Support staff, subscription eligibility, automatic redaction, email delivery and response times are outside this workflow. Use synthetic text and files. [Issue #301](https://github.com/susumutomita/TenkaCloudSimulator/issues/301)

The official boto3 `support` client uses AWS JSON 1.1, `POST /` and the target prefix `AWSSupport_20130415.`. Point the client at the authenticated simulator's numeric loopback address, sign dummy exercise requests for `support` in `us-east-1`, and supply the usual local access token. The [embedded reference](/_simulator/docs/support.html) sends the same requests in a signed-in browser. For each request, the gateway checks the exact `support:<Operation>` action on `*` before accessing the database. These operations have no support-case resource ARN. One local namespace is shared by authorized participants of the same team. [AWS endpoints](https://docs.aws.amazon.com/general/latest/gr/awssupport.html) · [AWS authorization reference](https://docs.aws.amazon.com/service-authorization/latest/reference/list_awssupport.html)

| Operation | Inputs and observable result |
| --- | --- |
| CreateCase | A subject of 1–256 characters and `communicationBody` of 1–8,000 characters create the case and its first message atomically. The reply carries its `caseId`. A case may use an existing temporary attachment set. Local case languages are `en` and `ja`. |
| DescribeCases | Returns cases in descending display-ID order. Select by `caseIdList` (up to 100) or a decimal `displayId`. Resolved cases require `includeResolvedCases`. Set `includeCommunications` to false to omit message details. By default each result contains up to its five newest messages and a continuation for `DescribeCommunications`. |
| AddCommunicationToCase | An explicit `caseId` and `communicationBody` append one customer message to an open case. An attachment copy and its message commit together. The reply returns `result: true` after commit. The local subset refuses follow-ups to resolved cases. |
| DescribeCommunications | Returns newest messages first, their local author, time, and attachment IDs and filenames. Optional `afterTime` and `beforeTime` select an inclusive local time interval. |
| ResolveCase | An explicit `caseId` changes the case to `resolved` and returns the previous and final statuses. Resolving an already resolved local case reports that same state. |
| AddAttachmentsToSet | Send filenames and base64 bytes. Omitting `attachmentSetId` opens a temporary set. Adding more files preserves its original one-hour expiry. The cumulative limit is three files. The simulator accepts 64 KiB per file, within AWS's documented 5 MB limit. |
| DescribeAttachment | Supply an attachment ID from a saved message to retrieve its filename and original bytes. In boto3, the returned `data` member is bytes. Expiry of the temporary upload set has no effect on submitted files. |

The case and communication lists accept `maxResults` from 10 to 100. A continuation is bound to its operation, filter, local identity and running process. After restarting, begin a new listing. Previously saved cases, attachment IDs and submitted file bytes survive restart when the process uses the same `--state` path. The local retention interval for cases is twelve calendar months. The simulator bounds each team's retained state to 256 cases, 4,096 communications, 128 active temporary sets, and 32 MiB of staged and submitted attachment bytes. Expired data is reclaimed during successful writes. Resolve ends a case's working lifecycle. AWS Support defines no case-deletion operation.

Case bodies come only from local callers. The API refuses unsupported fields such as CC email recipients, severity/service/category selection and paid-plan settings. Dates on the case listing, post-resolution replies, service staff actions, temporary STS credentials, other signing regions, real file delivery and larger-file upload APIs are outside this subset.
