# Single-exchange HTTP observation abstraction

The model keeps raw cumulative header bytes, raw field count, CRLF/folded-line class, parsed version/status, informational count, original deadline and publication prerequisites separate. There is no opaque ValidResponse predicate. Production limits 8,192 bytes/64 fields/8 informational responses are scaled to 3/2/1. A parsed-library error is a separate transition; successful net/http parsing does not bypass explicit raw/protocol/status checks.

- `Construct` chooses only `/` or `/healthz`; invalid path cannot admit work. Concrete engine presence, nonnil lifetimes, committer interface and trusted peer IP/port are assumed inputs. `Request` abstracts the fixed GET/Host/Connection-close string's full write versus short/error write. There are no retries, caller-supplied headers, request body or alternate method. Transport Dial and conn.SetDeadline are abstract successful prerequisites here; their early error traces before Request are omitted, so this is not complete early-failure coverage. Concrete string encoding remains native-test evidence.
- `Admit` captures the minimum original caller/transport/eight-second deadline. The zero deadline class includes expiry during the preflight/admission/capture window, so a retained worker need not imply a still-live budget. Model clock starts at successful admission, not construction; `Tick` cannot renew the saved value. Pre-admission capacity failure leaves the transport untouched. External `Cancel` abstracts original lifetime/caller revocation; it is not a proof of AfterFunc scheduling or physical lease enforcement.
- `Raw` matches readHTTPObservationHeader's shared LimitedReader, cumulative raw-field count across informational blocks, CRLF requirement and rejection of obsolete folding. Field names, status-line grammar, duplicate Content-Length/Transfer-Encoding normalization and net/http behavior remain library obligations, not byte-parser proofs. The modeled byte counter records attempted block cost, including an over-limit block that is rejected; it does not claim the concrete LimitedReader actually reads beyond its cap. All raw class/size/count assumptions are explicit.
- `Parsed` separately rejects non-HTTP/1.0-or-1.1, out-of-range status and101, counts informational responses before advancing, and records the exact final status/header-receive time. Redirect/error statuses are not promoted. The fields counter is not reset for each informational response. Separate attempted-byte/field and informational-history witnesses detect counter resets even if a local admission check would otherwise appear satisfied.
- `bodyReads` denotes deliberate application body consumption or Body.Close draining. No such action exists in the baseline. It does not claim bufio performs no underlying read-ahead into bytes after the header; LimitedReader still bounds source reads. Published output contains status/timing only, not body/headers.
- `CheckBeforeClose`/`CloseReturn` abstract successful context/transport rechecks, intentional teardown, and actual CloseContext return. Only nil cleanup plus terminal cause exactly context.Canceled can reach final owner acceptance; a joined cancellation plus a real error is rejected. This is the transport's first selected terminal cause, not an aggregation or proof of absence of every concurrent pump failure. Separate checks around hook removal are aggregated; transport failure at that boundary is represented by the returned cause/context outcome, not a physical linearization proof.
- `OwnerReturn` and `CallerReceive` retain context/deadline checks after final owner acceptance and on caller receipt. The owner callback's return is an external trusted outcome, never evidence of authenticated/physical ownership. Caller timeout explicitly requests transport closure and produces zero observation even if late worker completion arrives. A requested close is not a cleanup-completion signal. `WorkerReturn` alone releases observation capacity.

Crucial debt distinction: CloseContext may return ErrDrainPending/uncertainty while real transport teardown remains outstanding. The observation worker can then finish and release its observation slot; transport retains its independent cleanup debt. The model does not incorrectly require physical transport settlement before every observation-slot release. Pending owner/cleanup calls can hold the worker slot after the caller times out.

This is a bounded adapter model, not HTTP compliance/net/http parser refinement, concurrent observers on one transport, multiworker capacity refinement, a real socket/VM, physical owner implementation, scorer authority, dependency security or production Battle.
