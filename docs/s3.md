# S3のバージョンとbucket設定

既存10操作にGet/PutBucketVersioning、ListObjectVersions、Get/Put/DeletePublicAccessBlockとGet/Put/DeleteBucketTaggingを追加。SDK/UI/Scalarは同じHTTP/stateを使う。CloudFormationのS3 Bucket（下記限定）に対応。ACL、bucket policy、account/organization public-access-block、access points、multipart、copy、conditional DELETE、Object Lock、lifecycle、replication、MFA Deleteは未対応。設定を無効にしてもpublic grantは作られない。

## 保存と削除

未設定bucketではPUTが現在値を置換し、DELETEは永久削除。Enable後のPUTにはopaque version IDが付く。DELETEは新しいdelete markerをcurrentにし、通常GET/HEADは404。特定markerのGET/HEADは405、x-amz-delete-markerとLast-Modifiedを返す。versionIdは1–128のprintable UTF-8 bytes（当Simulatorが生成するIDはhexまたはnull）。versionIdを指定したDELETEはその版だけを永久削除する。currentを消すと残った最新の版がcurrentになる。marker除去で旧objectが戻る。取り消した版自体は復元できない。

Suspendedは既存のnumbered versionsを保持し、PUT/DELETEでnull版を置換する。再Enableしてもnull版/markerを消さない。無効状態へ戻す操作はない。未設定時GetBucketVersioningはStatusを省略。設定の反映は即時であり、実AWSの伝播待ち時間は再現しない。

AWS所有のaws_s3_versionsが履歴を保存する。provider中立objectsはcurrentの共有viewで、両方を単一immediate transactionで変更する。既存SQLiteの無version objectは内容を保持したnull版として遅延importする。旧状態ファイルのschema versionは変更しない。new bucketはAWSの現在の既定に合わせpublic-access-blockの4値をtrueで初期化。旧bucketの未設定値を勝手に書き換えない。

Content-Typeは1024 UTF-8 bytes以下に制限し、body以外の履歴metadataによる無制限な増大も防ぐ。keyは既存の1024 UTF-8 bytes上限。

64 MiB/10000の保存quotaは全retained versions/markersと未import objectを数え、current viewの重複を除く。markerも1entry、null置換は置換対象だけを解放。上限拒否/SQL失敗で履歴とcurrentの一部を残さない。bucket削除はcurrentが空でもhistory/markerが残っていればBucketNotEmpty。自動削除やquota逃れのための履歴削除はしない。

## IAMとページ送り

version指定GET/HEADはs3:GetObjectVersion、DELETEはs3:DeleteObjectVersion、一覧はs3:ListBucketVersions。通常版は既存GetObject/DeleteObject/ListBucket。Get/PutBucketVersioning、Get/PutBucketPublicAccessBlockはbucket ARNへ評価。DeletePublicAccessBlockにもPutBucketPublicAccessBlockを使用。実署名/STSではなく既存local token境界と限定identity policyの範囲。

ListObjectVersionsはkey昇順・同key内の新しい版から返す。prefix/delimiter/max-keys(0–1000)/encoding-type=urlとkey-marker/version-id-markerに対応。cursorのIDはopaqueで、既存の同じkeyの版を指定する。削除されたcursorはInvalidArgumentとして再取得を要求する（実AWSの全cursor挙動とは一致を保証しない）。Owner/checksum/restore metadataは省略。unsupported/重複/混在queryやXML fieldsは明示エラー。

## 検証と一次資料

S3Versionsの有限モデルはenabled history/current一致とhistory orphan禁止を確認し、currentだけを見てbucket削除するmutantの反例を必須とする。suspension/quota/SQL/実装全体の形式証明ではない。

Go race: legacy persistence、2 DB接続の同時writes、conditional PUT、失敗時rollback、history quota、current復元、全history削除後のbucket cleanup。HTTP: marker status/headers、ARN/IAM、ページ送り、XML validation。実binary/boto3/browser: UI有効化→SDK更新→削除→旧版download→marker除去→復元、public block編集/confirm、別teamのhistory不可視、PC/mobileと外部通信0。既存問題wp2shellはWAF・custom resource lifecycle・関数内HTTP採点・ホスト採点連携が未完のため選択不可のまま。S3/SSMのLambda SDK bridgeとCFN API Gateway対応だけでは問題全体の完走にならない。

契約は[AWS PutBucketVersioning](https://docs.aws.amazon.com/AmazonS3/latest/API/API_PutBucketVersioning.html)、[DeleteObject](https://docs.aws.amazon.com/AmazonS3/latest/API/API_DeleteObject.html)、[GetObject](https://docs.aws.amazon.com/AmazonS3/latest/API/API_GetObject.html)、[ListObjectVersions](https://docs.aws.amazon.com/AmazonS3/latest/API/API_ListObjectVersions.html)、[PutPublicAccessBlock](https://docs.aws.amazon.com/AmazonS3/latest/API/API_PutPublicAccessBlock.html)を確認。実AWS全機能・認証済console pixel一致は未検証。

## CloudFormationとユーザータグ

AWS::S3::BucketはBucketName（省略時はstack固有のDNS名）、VersioningConfiguration.Status、4つのPublicAccessBlockConfiguration値、Tagsだけを受け付ける。Refは名前、GetAttはArnのみ。未知属性・誤った型は拒否。S3/SSM/IAMの作成とclaimは同一transaction。bucket claimはリージョンを跨ぐglobal namespaceで、手動削除後も他stackによる名前取得を拒否する。既存bucketはadoptしない。

DeleteStackは全historyが空の場合だけbucketを削除し、tags/configも同時に消す。失敗時は先に削除を試みたSSM等もrollbackする。driftで既に消えたbucketは所有者のstack cleanup時にはskipする。非同期のAWS stack lifecycle/Events、UpdateStack、DeletionPolicy/Retain、S3暗号化/website等は未対応。現在のAPIは同期の限定subsetで、削除不可はAPIエラーとして返す。

タグは最大50、key1–128/value0–256 Unicode文字。Unicode文字/数字/spaceと_.:/=+-@、aws: prefix禁止。native PUTは全置換、64KiB以下のXMLと対応checksumが必要。空のset/DELETEはタグを削除し、GETは未設定をNoSuchTagSetで返す。先頭/末尾spaceは保持する。条件付きABAC、課金、AWS system tags、stack-level tags自動伝播、object taggingは未対応。CloudFormation resource TagsとSDK/CloudscapeのProperty→Tagsは同じaws_s3_tagsを使う。

CFNのCreate/Deleteにはstack ARNの許可に加えて、生成/削除対象のS3/SSM/IAM actionsと実ARNの許可が必要。CAPABILITY_IAMは承認表示であり権限付与ではない。要求開始時のcaller policyをsnapshotし、Deleteは同じDB transactionでownerを解決・全action評価してから変更する。service RoleArn/実STS/trust評価は引き続き未対応。既存のCFN-onlyポリシーは新しい作成/削除でAccessDeniedになるため、必要なresource actionsを明示的に付与する。冪等Create retryは新規mutationをしないので、保存したstack ARNのみ評価。
