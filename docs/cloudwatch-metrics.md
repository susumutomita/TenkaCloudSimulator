# CloudWatch custom metric statistics

The simulator accepts `PutMetricData` and `GetMetricStatistics` at the AWS root and its standard local alias `/_simulator/providers/aws/` using the 2010-08-01 Query protocol. The pinned boto3 CloudWatch client uses the signing name `monitoring`. Use the simulator's numeric loopback URL and local access token. The two IAM actions are `cloudwatch:PutMetricData` and `cloudwatch:GetMetricStatistics`, each with resource `*`. A participant's selected identity and saved policy control access. A dummy SDK signing key selects the destination. The local IAM subset rejects policy conditions such as `cloudwatch:namespace`. [AWS service authorization](https://docs.aws.amazon.com/service-authorization/latest/reference/list_amazoncloudwatch.html)

A successful write appends every raw observation to the team's SQLite database in one transaction. Sending the same datum twice contributes two samples. A metric is identified by region, custom namespace, name and the complete set of dimension name/value pairs. Units form separate series for aggregation. The region must be one of the simulator's supported AWS regions.

| Input | Accepted subset |
| --- | --- |
| Request | Form-encoded POST to `/`, exact `Version=2010-08-01`. Put also accepts one gzip member. Both the wire and expanded body have a 1 MiB local limit and the form accepts at most 10,000 fields. |
| Batch | 1–1,000 individual numeric `Value` samples. Values must be finite and between −2³⁶⁰ and +2³⁶⁰ inclusive. |
| Dimension | Up to 30 distinct names. Printable ASCII names are 1–255 bytes and values are 1–1,024 bytes. Both require a non-space character. Names cannot begin with a colon. |
| Namespace and name | A printable custom namespace of up to 255 ASCII characters outside `AWS/` and without a leading colon. Metric names accept up to 255 Unicode characters without control characters. Both require a non-space character. |
| Timestamp | RFC 3339. Each write uses one server time for omitted timestamps and accepts times from 14 days before that time through two hours after it. |
| Resolution and unit | Standard 60-second resolution. An omitted unit becomes `None`. The native standard unit names are accepted. |

A statistics query rounds its start down to the nearest UTC minute, includes that rounded start and excludes its end. Supply a positive period in seconds that is a multiple of 60. The simulator groups observations into periods starting at that rounded start and returns only buckets containing data. Choose one or more of `SampleCount`, `Sum`, `Average`, `Minimum` and `Maximum`. Average uses all raw samples in the period. Pass a unit to select it or omit the unit to receive separate unit/time datapoints. The local limit is 1,440 requested time buckets and 1,440 returned datapoints across all units. [AWS PutMetricData](https://docs.aws.amazon.com/AmazonCloudWatch/latest/APIReference/API_PutMetricData.html) · [AWS GetMetricStatistics](https://docs.aws.amazon.com/AmazonCloudWatch/latest/APIReference/API_GetMetricStatistics.html)

Raw samples are queryable for 15 days. An authorized successful write prunes older rows in the same region and namespace. Queries, denied requests and failed batches preserve stored rows. Local limits are 10,000 stored samples per region/namespace and 100,000 stored samples per team database. Expired rows in other namespaces still occupy the team quota until a successful write prunes that scope. Teams can dispose of their own simulator database to clean up a practice run.

The native Query SDK and HTTP API support both publishing and reading samples. ListMetrics, GetMetricData, dashboards, Insights, metric math, percentile and statistic-set ingestion, Values/Counts arrays, entities, high resolution, automatic collection and long-term rollups are outside this subset. CloudWatch Logs uses its own API and storage. [CloudWatch Logs](cloudwatch-logs.md)

## Local metric alarms

The same native Query endpoint adds [PutMetricAlarm](https://docs.aws.amazon.com/AmazonCloudWatch/latest/APIReference/API_PutMetricAlarm.html), [DescribeAlarms](https://docs.aws.amazon.com/AmazonCloudWatch/latest/APIReference/API_DescribeAlarms.html) and [DeleteAlarms](https://docs.aws.amazon.com/AmazonCloudWatch/latest/APIReference/API_DeleteAlarms.html). These operate on actual saved metric samples; they do not accept a caller-supplied alarm state. The initial state is INSUFFICIENT_DATA. Updating a configuration preserves its state until real evaluation.

Supply a printable ASCII AlarmName (1–255 bytes), custom Namespace/MetricName, optional complete Dimensions, explicit Unit, one basic Statistic, Period=60, EvaluationPeriods=1, a finite threshold and one of GreaterThanThreshold/GreaterThanOrEqualToThreshold/LessThanThreshold/LessThanOrEqualToThreshold. DatapointsToAlarm is absent or 1, and TreatMissingData is absent or `missing`. AlarmDescription is bounded UTF-8 XML text; ActionsEnabled is stored. Nonempty AlarmActions/OKActions/InsufficientDataActions, tags, metric math, percentiles, composite alarms, history and SetAlarmState are unsupported. No SNS or other alarm action is emitted.

Evaluation uses matching region, namespace, metric name, canonical full dimension set and Unit in `[floor(now)-60 seconds, floor(now))`, with UTC minute boundaries. It computes the selected statistic from actual raw observations. No matching samples means INSUFFICIENT_DATA and a null unmeasured value, distinct from a measured zero. A real value is compared with the saved threshold to produce OK or ALARM. StateReason and StateReasonData describe the actual count, window and comparison.

Accepted PutMetricData updates matching alarms in the same SQLite transaction as its observations and retention pruning. A failed or interrupted derived update rolls back the complete write. DescribeAlarms and store startup also evaluate saved alarms; an admitted read can therefore update derived state. This is an explicit local profile: there is no background scheduler or AWS timing/SLA claim, and older samples outside the completed minute are not used as AWS's extended evaluation-range fallback.

The alarm ARN is `arn:aws:cloudwatch:{region}:000000000000:alarm:{AlarmName}`. Each named create/update/read/delete evaluates its own `cloudwatch:` action on that exact ARN before observing or changing alarm state. DescribeAlarms without a name requires resource `*`. This profile accepts at most one AlarmNames member for describe/delete, a prefix and StateValue filter for lists, optional MetricAlarm type, MaxRecords 1–100 and an opaque region/query-bound NextToken. Continuations reauthorize and are not frozen snapshots. Native optional empty lists are accepted; unknown or mixed list members are refused.

Limits are 100 alarms per Region and 1,000 per team. Delete removes the selected alarm, leaving metric observations intact. Two teams use separate processes, databases, policies and cursor authorities. Restart preserves configurations and recomputes their actual local state; it does not fabricate a delivery event or support case.

The simulator evaluates alarms from explicitly published observations. Native alarm actions and notification delivery are outside this threshold-evaluation workflow.

## Read metric alarms in the console and API reference

Open **Services → CloudWatch** to browse metric alarms in the selected region. You can also enter an exact alarm name. Each detail view queries the native alarm and then requests its configured statistic for the same namespace, dimensions, unit and completed UTC minute. A missing datapoint and a measured zero display separately. **Refresh alarm** reads both APIs again. The alarms list requires `cloudwatch:DescribeAlarms` on `*`. An exact lookup accepts permission on that alarm ARN. The statistic read requires `cloudwatch:GetMetricStatistics` on `*`.

In the API reference, open **Shared AWS JSON/Query endpoint**, select the URL-encoded request body and choose one of the five **CloudWatch** examples. Set `X-Simulator-Service` to `monitoring`, use your session’s region and clear `X-Amz-Target`. The examples share the practice series `Training/Observability / QueueDepth` with dimension `Queue=practice` and unit `Count`. Replace the statistics example's start and end with a recent completed UTC minute. Each PutMetricData Send appends another sample. DeleteAlarms removes the named alarm. Published samples age out under the metric store's retention policy. The separate CloudWatch Logs console reads events explicitly ingested into the Logs API.
