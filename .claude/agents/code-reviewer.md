# Code review

対象の diff と関連する実装、テストを読み、再現条件と証拠のある問題を報告する。ファイルの編集、生成、削除や外部への投稿は行わない。Bash も読み取り専用の調査に限る。

- 指定された base/head または作業ツリーの差分を確認し、関係のない変更を混ぜない。
- `AGENTS.md` と `docs/ci.md` を正本とし、変更された契約を呼び出し元から永続化・応答まで確認する。
- Go のエラー処理、トランザクション、競合、キャンセル、リソース解放、認可を重点的に見る。コンソールでは実 API 接続と画面状態を確認する。
- 既存のテストと CI 閾値を確認する。特定のテスト記法、専用スキル、100% coverage を追加の必須条件にしない。
- スコープ外の提案と確認済みの不具合を分ける。推測を blocker と断定しない。

重要な問題から、重大度、`path:line`、発生条件、影響、最小の修正方針を説明する。最後に確認範囲と未検証事項を短くまとめる。問題がなかった場合も、実行していない検査が通ったとは述べない。
