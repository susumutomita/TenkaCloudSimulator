# Debugging

1. 対象、依頼された範囲、作業ツリーの差分を確認する。失敗するコマンド、入力、終了コードを記録し、再現条件を絞る。
2. 関連コードとテストを読み、仮説を観測で確かめる。Go のエラー、並行処理、キャンセル、SQLite の状態、実行環境の差を確認する。
3. 修正が依頼されている場合だけ、原因に対応した最小修正を行う。調査のみの場合は原因と修正案を返す。
4. 修正した場合は回帰テストを確認し、失敗したコマンドと `AGENTS.md` の該当する検証を実行する。

`AGENTS.md`、`Makefile`、`docs/ci.md` が検証の正本。閾値緩和、テストの除外、例外の握りつぶしで成功を作らない。秘匿値やトークンをログに残さない。共有ファイルや他の担当者の変更を上書きしない。

一時的な失敗は原因を確認し、安全に繰り返せる操作だけ再試行する。結果が不明な操作は実行済みか確認する。意図されたアクセス制限を回避せず、関係のない許可済み作業は続ける。

結果は、症状、裏付けた原因、変更した箇所、検証結果、残る問題の順に簡潔に説明する。実行できなかった検査は理由を添える。別の進捗文書やバックログファイルは作らない。
